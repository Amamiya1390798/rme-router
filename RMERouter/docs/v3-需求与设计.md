## 1 目标与设计原则

RME Router 是一个 macOS 原生应用：在 TotalMix FX 2.1 之上，用“谁的声音送到哪里”的方式管理 MADIface XT、12Mic、OctaMic XTC 之间的路由，并把 RME Connector 的前级控制整合进来。TotalMix 仍在后台运行，负责实际的混音和路由；本 App 是更清楚的操作界面，不是替代引擎。

已确认：原版 MADIface XT 可以在 TotalMix FX 2.1 下正常使用（用户实机验证）。

**设计原则**

1. **只显示在用的东西。** 默认只出现接了线、有名字或有路由的通道，不出现三大排 192 路通道条。
2. **以“输出”和“声音来源”为中心。** 例如“12Mic 耳机现在送出什么”，而不是“先选输出 Submix，再找输入推子”。重心是 RME 三台设备之间的路由；P16 等外接设备只是可选的终点。
3. **一条路径一张图。** 跨设备的信号从哪来、经过哪、到哪去，在一个界面里看清，每一段带状态。
4. **以接口和通道为锚点。** 主标签是“接口 · 通道”，RME 原名（M1-9）作副标签，用户名最后且可省。
5. **先诊断，后操作。** 没声音时先告诉你哪一段断了，再给出改法。
6. **改动可预览、可撤销，从安静开始。** 新建发送默认从静音起步，确认后再推上去。

## 4 主界面与交互概念

窗口分三栏：左侧是视图切换和设备列表，中间是当前视图，右侧是检查器。“输出”是默认首页；任何输出卡上的“送一路声音”打开跨设备路由流程。

| 视图 | 回答的问题 | 主要内容 | MVP |
| --- | --- | --- | --- |
| 输出 | 每个输出在送什么？ | 按 MADIface XT、12Mic、XTC 分栏，每个在用的输出一张卡，标明是混音发送、直通还是 8 路块；外接设备单独列为终点 | 是（只读起步） |
| 信号流 | 这路声音从哪来、到哪去？ | 选中一路即画出完整路径，每段一个状态点 | 是 |
| 前级 | 麦克风输入正常吗？ | 12Mic 与 XTC 的增益、48V、相位、电平表，整合 RME Connector 的功能 | 12Mic 是 |
| 体检 | 哪里配置不对？ | 时钟与采样率、链路、控制路径的检查结果，带中文说明和改法 | 是 |
| 矩阵 | 精确地看全部 | 按控制域分层：TotalMix 发送、12Mic 直通、XTC 8 路块 | 否 |

**送一路声音（路由流程）**：选来源 → 选去处 → App 算出经过哪些设备、每台怎么设置 → 预览（自动 / 沿用现有 / 需人工）→ 加入待应用 → 确认后写入并回读核对。

**通用交互**

- 状态只用四种：已确认（实心点）、推断（空心点）、未知（灰色虚线）、有问题（警示红，带图标）。
- 所有写入先进入底部“待应用”栏；点“应用”才发送，可整体撤销。
- 场景：保存 TotalMix、12Mic 和 XTC（读取成功时）的路由与前级；调用前先显示差异。

## 6.1 链路表示法（全项目统一）

每一路信号都用“设备.接口.方向:通道”的地址表示，名字只是别名；一条路径是“设备内路由 →”和“线缆 ⇒”交替组成的序列。代码（`Notation.swift`、`ChannelRef`）、界面、文档和体检报告都用这一套。

| 部分 | 规则 | 例 |
| --- | --- | --- |
| 设备 | 小写 ID，固定 | `xt` `12mic` `xtc`；外接设备自定，如 `p16i` |
| 接口 | 优先用设备协议里的名字，其次面板名；小写加下划线 | `madi_optical`、`madi1`、`adat1` |
| 方向 | `in` 或 `out`，以该设备自身为准 | `xt.madi1.in` 是 XT 收 MADI 1 |
| 通道 | 从 1 起；`a-b` 为连续范围 | `:9`、`:1-2`、`:1-8` |
| 别名 | 只显示，不作键 | `xt.madi1.in:9` 别名 M1-9 |

**端口登记表（标“待核”的以实机为准写进黄金配置）**

| 设备 | 端口 ID | 对应 | 单速通道 |
| --- | --- | --- | --- |
| MADIface XT | `xt.madi1.in/out`、`xt.madi2.in/out`、`xt.madi3.in/out` | TotalMix 的 M1/M2/M3；哪个是光口、哪个是同轴待核 | 64 |
| MADIface XT | `xt.mic.in`、`xt.aes.in/out` | 前面板 Mic 1–2（TotalMix 名 `Mic n`）、AES（`AES`，立体声） | 2 / 2 |
| MADIface XT | `xt.an.out`、`xt.phones.out` | 模拟输出 AN 1/2（回放名 `AN 1/2`；输出名可能被控制室改成 `Main`）、耳机（回放名 `PH`；输出名可能为 `Phones 1`） | 2 / 2 |
| MADIface XT | `xt.playback.in` | 电脑回放：TotalMix 回放 n 即 `:n`（按定义映射，不推断） | 198（TotalMix 实测） |
| 12Mic | `12mic.analog.in` | Mic 1–12（JSON：analog） | 12 |
| 12Mic | `12mic.madi_optical.in/out`、`12mic.madi_coaxial.in/out` | SFP 光口、同轴（JSON 名） | 64 |
| 12Mic | `12mic.phones.out` | 耳机 L/R（JSON：phones） | 2 |
| OctaMic XTC | `xtc.mic.in`、`xtc.madi.in/out`、`xtc.adat1.out`、`xtc.adat2.out` | 面板名；AES 口待核 | 8 / 64 / 8 / 8 |
| 外接 P16-I | `p16i.adat_a.in`、`p16i.adat_b.in` | ADAT A（时钟来源）、B | 8 |

**跳的写法**：设备内路由 `源 →[域 类型 参数] 目标`；线缆 `输出口:n ⇒ 输入口:n`，通道号不变。

**不变量**（1–3 由 PathInvariants 检查，4–5 由路径搜索检查，6 由类型保证，7 由适配器测试保证）

1. 路由只在一台设备内，方向 in → out。
2. 线缆只在两台设备之间，方向 out ⇒ in，通道号不变，且在连接表里登记。
3. 每一跳的起点是上一跳的终点；两根线缆不能直接相连。
4. 通道号不超过当前格式上限：MADI 单速 64/56、双速 32/28；ADAT 8/4。
5. XTC 块路由覆盖 8 个相邻通道，块内偏移不变。
6. TotalMix 发送一定带电平，直通和块路由不带。
7. Global OSC 从 0 编号，只在适配器里换算；地址层永远从 1 起；对照表从 TotalMix 读回，不用公式推算。

**示例：XTC Mic 1/2 → 12Mic 耳机**

```text
xtc.mic.in:1-2
  →[xtc 8 路块]           xtc.madi.out:1-2
  ⇒                       xt.madi2.in:1-2            别名 M2-1/2
  →[totalmix 发送 0.0 dB] xt.madi1.out:33-34
  ⇒                       12mic.madi_optical.in:33-34
  →[12mic 直通]           12mic.phones.out:1-2
```

实机问题 3：`12mic.analog.in:1 →[12mic 直通] 12mic.madi_optical.out:9 ⇒ xt.madi1.in:9`（别名 M1-9）。

## 6.2 12Mic JSON 接口（只读客户端）

**出处（A）**：12Mic 手册 Remote Control Overview，https://docs.rme-audio.com/12mic/150-1c_remote_overview/（2026-10-25 核对）。

- 传输：HTTP POST `http://<地址>/api/v2/self`，`Content-Type: application/json`。地址：USB 直连 `http://172.20.0.1`，网络 `http://12mic.local`（部分系统要写 `12mic.local.`）。需在设备 STATE → remote 打开 **HTTP Remote**。
- 读：键的值传 `null`，设备回同结构的当前值；写：传新值。没有推送，全部靠轮询。
- **没有任何认证**：网络上任何人都能改设置。所以只读客户端发出的请求体必须**所有叶子都是 `null`**（`TwelveMicReadGate`），写入以后另走待应用栏 + 确认。
- 本 App 读取的键：`device/entity_name`（在线探测）、`input/analog`（前级）、`clock`（`current_sampling_rate`、`source`、`sources/<名>/rate|sync`、`soundness/state|cause`）、`output/madi`（`mode` 56/64、`framesize` 48/96）、`routing`（输出口 `phones`、`madi_coaxial`、`madi_optical` → 通道 `"1"…"64"` → `["<输入口>", 通道]` 或 `["unrouted", 1]`）。
- 前级（只读）：`input/analog/<n>` 下 `label`（字符串）、`gain`（dB）、`p48`、`phase`、`hiz`、`trs`、`gain_autoset`（布尔）、`gain_group`、`type`（如 "combo"）。手册未写各字段的确切类型，解析时布尔也接受 0/1，读不到的字段记为 unknown，不猜默认值。数据模型：`PreampChannel`（RMECore），挂在 `DeviceSnapshot.preamps`。
- 输入口名：已登记 `analog`、`madi_coaxial`、`madi_optical`；其余（如 AVB）手册未列全，读到时不生成路由，计数提示。
- 待实机核对：未锁定的 MADI 源 `rate` 的取值（代码按“非整数即未锁定”处理）；路由里输入口名的完整列表。

## 6.3 OctaMic XTC MIDI SysEx（阶段 C 前置，2026-10-25）

**出处（A）**：OctaMic XTC 用户手册 v1.3 第 29 章 “MIDI Implementation OctaMic XTC”，https://www.rme-audio.de/downloads/octamicxtc_e.pdf（2026-10-25 核对）。此前“XTC 路由协议编号未知（D）”的结论作废。

- 格式：`F0 00 20 0D 69 <设备 ID> <命令> <数据…> F7`。设备 ID 0–7（XTC 面板 Options → General Settings 设置）。
- 命令：`10` 请求全部参数（含电平）；`11` 请求电平；`12` 请求变化的参数；`20` 设置参数（可多个）；`30` 设备发出的参数。
- 设置（`20`）的数据：每个参数 4 字节 `索引 LSB MSB 置位标志`；设备发出（`30`）的不带置位标志，每个参数 3 字节（**按手册推断，待实机核对帧格式**）。所有数据字节 ≤ 0x7F。
- 参数（与本 App 相关的）：

| 索引 | 内容 | LSB / MSB | 置位标志 |
| --- | --- | --- | --- |
| 0–7 | Mic 1–8 通道设置 | LSB：位 0–5 增益（0 = 0 dB，n = n+9 dB，1…56 → 10…65 dB），位 6 反相；MSB：位 0 静音、1 AutoSet、2 +48V、3 Pad（1–4）/ Instrument（5–8）、4–6 编组 | 0x01 增益、0x02 反相、0x04 静音、0x08 AutoSet、0x10 48V、0x20 Pad/Inst、0x40 编组 |
| 14 | Digital Routing：ADAT 1 输出 / ADAT 2 输出 | LSB / MSB 各一个来源（值表 2） | 0x01 / 0x02 |
| 15 | AES 输出 | 同上 | 同上 |
| 16–19 | MADI 输出 1–8 / 9–16 … 57–64 | 每个索引两块（LSB 前一块，MSB 后一块） | 0x01 / 0x02 |
| 20 | USB 录音 9–16 / 17–24 | 同上 | 同上 |
| 21 | 时钟 | LSB 位 0–3 时钟源（internal、WCK、AES1…4、ADAT、MADI）；MSB 位 0–3 采样率序号（32k、44.1k、48k、64k、88.2k、96k、128k、176.4k、192k） | 0x01… |
| 22 | MADI 设置 | LSB 位 2 格式（0 = 56，1 = 64），位 3 帧（0 = 96k，1 = 48k） | |
| 25 | Lock/Sync（仅随全部参数发出） | LSB Lock、MSB Sync：位 0 WCK、1–4 AES1–4、5 MADI、6 ADAT | |
| 26–31 | 电平（仅发出） | 每字节一路：126 = OVR；125…95 → (v−125)×0.2 dB；94…23 → (v−107)×0.5 dB；22…1 → v−65 dB；0 = 下溢 | |

- 值表 2（数字路由来源）：0 Mic 1–8、1 ADAT IN、2 AES IN、3–10 MADI 1–8 … 57–64、11–15 PB 1–8、5–12、9–16、13–20、17–24。
- **控制冲突（硬性）**：手册写明 XTC 的 MIDI 控制输入只选一个来源，MIDI Remote 与 TotalMix Aux Device 不能同时使用。本 App 发 SysEx 等同一个控制来源：**默认不向 XTC 发送任何消息**，须在“连接”页明确打开“由本 App 控制 XTC”；打开时体检 R9 检查是否与 TotalMix Aux Device 冲突。
- 写入（`20`）同样走待应用栏与确认（第 7 节），只允许路由（14、16–19）与前级（0–7 的增益、反相、48V）；打开 48V 的规则同第 7.2 节。
- **同一索引收发含义不同（硬性）**：发往设备时 25 = 加载/保存预设、26 = 编组增益增减、23 = MIDI 来源选择（改错会让本 App 失去控制）。发送闸门 `XTCSendGate` 只放行命令 `10`/`11`/`12` 与命令 `20` 下索引 0–7（置位标志只能是 0x01/0x02/0x10 的组合）和 14、16–19（标志 0x01/0x02）；其余一律拦截，并且增益限定 0–60 dB（与第 7.2 节一致）。
- **App 接入**（“连接”页 XTC 一节，全部默认关）：
  1. 选 MIDI 输入、输出端点和设备 ID（0–7）；
  2. 开关“读取 XTC”：打开后才向 XTC 发请求（只发命令 `10`），读到的路由、时钟、前级替换演示数据；
  3. 勾选“已确认 TotalMix Aux Device 与 MIDI Remote 没有在控制 XTC”后，才能打开开关“允许本 App 改动 XTC”。
  - 快照里登记两条控制路径：`this-app`（active = 允许改动）与 `totalmix-aux`（active = 未勾选上面的确认），R9 据此判断冲突。
  - 允许改动且读取成功时，XTC 路由能力从“人工”变为“可写”：跨设备送声里的 XTC 步骤变成自动的待应用改动（8 路块），走待应用栏、确认、回读核对、撤销；前级页 XTC Mic 1–8 可改增益、反相、48V。
  - XTC 增益只有 0 dB 与 10–65 dB 两段：本 App 限 0–60 dB，1–9 dB 按 10 dB 发送（确认框显示实际值）。
- 收发：CoreMIDI，MIDI 1.0 协议的 UMP 事件列表；SysEx 用 UMP 7 位数据包（类型 3，每包最多 6 字节，状态 完整/开始/继续/结束）。端点由用户在“连接”页从列表里选（XTC USB 端点名未核对，不按名字猜）。

### 6.4.2 声卡侧（XT 驱动 / TotalMix）的模型

TotalMix 的三行就是 XT 驱动的全部声音入口和出口：

| 行 | 数量 | 含义 | 本 App 地址 |
| --- | --- | --- | --- |
| 硬件输入 | 196 | Mic 1–2、AES、MADI 1–3。**电脑录音通道 = 硬件输入，一一对应、固定不可改**（驱动录音通道 n 就是硬件输入 n） | `xt.<接口>.in:<n>` |

- **自洽检查**（新增体检规则，实现时编号 R15 起）：
  1. 登记的 XT 输入 / 输出总数 = TotalMix 读回的通道数（196 / 198 / 198）；
  2. 接上后，Core Audio 报告的 XT 输入 / 输出路数与上表一致；
  3. 每个 TotalMix 通道都能映射到唯一一个接口通道，没有两个映射到同一个；
  4. 接线两端类型相容：光口对光口、同轴对同轴；SFP（LC）对 SC 要转接线并提示；ADAT 对 ADAT；
  5. 12Mic、XTC 的通道数与各自协议（JSON 端口、SysEx 值表）一致。

### 6.4.3 视图模式（“设备”页）

**防杂乱的规则（硬性）**：
- 默认只画**实物线缆**（接线表），每根线一条：从接口垂直引出，在设备之间的缝里横走（每根线一条走道，互不重叠），再垂直进目标接口；颜色区分种类（MADI 光纤、同轴、ADAT、USB）；
- 设备内部路由**不常驻显示**；选中一个接口或通道后，只画它的去向与来源，其他变暗；
- 64 路的 MADI 口在面板上是一个接口；选中后展开 8 路一组的通道格，不在面板上画 64 根线。

**布局**：
- 每台设备一块面板，可切换“前 / 后”，用官方产品图，接口上叠可点的热区；机架式排列：12Mic 在上，XT（半机架）居中、旁边是“这台 Mac”与 P16-I，XTC 在下；
- 接口上显示状态：有信号（电平）、Lock / Sync、未接线；
- XT 下方是 **TotalMix 式通道条列表**，分三行：硬件输入、软件回放、硬件输出。每条显示名字、电平、静音、相位、音量 / 声像，直接复用第 7.8 节；
- “电脑”节点（第 8.2 节 E2）在 XT 的 USB / PCIe 口外侧。

**与 TotalMix 同步（硬性）**：
- 客户端一直在收 TotalMix 发来的变化。App 每秒检查一次有没有新变化（不算电平），有就重建对照表与快照，所有页面同时更新，不用再按“读取设备”。
- 立体声配对以 TotalMix 为准：输出页的立体声卡、设备页通道条、检查器都按 TotalMix 的 `stereo` 决定合并或拆分；只有 TotalMix 没报（12Mic、XTC、或还没读到）时，输出页才按“来源能一一配对”推断。

**麦克风去向（通道条）**：
- 点一条输入（或回放）通道条，画出它到每个硬件输出的线，线上标电平；
- 硬件输入条上写明“录音 n”：**硬件输入 n 固定就是电脑录音第 n 路，不需要拉线**；选中时在回放那一行左侧显示一个“电脑录音 n（DAW 输入）”的虚线条，并画线过去，让“进电脑”也能看见；
- 输入条名字下面写它的源头，例如 MADI 1 输入 9 显示“← 12Mic Mic 1”（沿接线和路由追到底）；
- DAW 那一侧（哪条轨道用了这一路）暂不做（第 8.2 节 E5）。

**拉线**（第 8.2 节 E4 的落地）：
- 从输入接口 / 通道条拖到输出接口 / 通道条，同设备内按各自规则变成待应用改动：
  - TotalMix：新建发送 -30 dB；
  - 12Mic：路由；
  - XTC：8 路块；
- 跨设备只能连实物接口（改接线表）；
- 拖到“软件回放”拒绝并说明原因；拖到“电脑录音”走 loopback 并明确确认。

## 7 Global OSC 使用要点与安全规则

**出处（A）**：RME 官方协议表 `OSCProtocoll_260721.ods`（“OSC-Commands TotalMix FX 2.1 beta 2 Global OSC”，2026-07-21），下载自 https://www.rme-audio.de/downloads/globalosc_protocol_b2.zip（2026-10-25 核对）。论坛讨论（A2/B）只作补充；两者冲突时以协议表为准，协议表更新后重新核对本节。

**设置**：Options 里打开 OSC Control；Settings → OSC 把兼容模式设为 Global OSC，在 Details 设端口与带宽限制（RME 建议从 500 kByte/s 起）。**关闭“Follow Submix”**（协议表要求）。本 App 用独立端口，避开 iPad TotalMix Remote 和 Stream Deck 插件（7008/9008）。同机用 127.0.0.1；开 Wi-Fi 时 TotalMix 可能绑定 IPv6（论坛，B），此时改用 ::1。Channel Layout 里隐藏的通道对 Global OSC 同样隐藏（可在选项里改为仍接收）。

**编号与取值（协议表原文）**

- 通道号（input / playback / output）从 0 起；预设、快照、布局等“编号”从 1 起。
- 立体声通道：用左声道编号寻址；标 L/R 的参数，右声道用编号 + 1。
- 值一律是浮点（也接受 T/F 与整数）；`name` 等为字符串。
- 标 (f) 的触发类命令：值可省，但若带值且小于 0.5 会被忽略。
- 状态约每秒发一个参数。

| 地址 | 含义 | 本 App 用途 |
| --- | --- | --- |
| `/mix/in/<输入>/<输出>/fader`、`/mix/pb/<回放>/<输出>/fader` | 混音节点电平，dB 浮点；-300 dB 为关 | 读出 TotalMix 路由（节点 > -65 dB 视为一条发送） |
| `/mix/…/faderlin` | 同上，推子位置 0–1（换算公式见协议表“Fader curve”页） | 界面推子 |
| `/input/N/…`、`/playback/N/…`、`/output/N/…` | 通道参数：`mute`、`stereo`、`name`、`volume`、`48v` 等 | 别名、静音、立体声配对、体检 R13 |
| `/sendall` | 触发发送全部参数；值 2 = 只发电平 > -65 dB 的混音节点 | 启动时读全量（用 2.0） |
| `/sendchan/<input\|playback\|output>/<N>` | 触发发送该通道全部参数（总线在前） | 单通道刷新 |
| `/sendmix`、`/sendsubmix/<输出>` | 触发发送混音节点；1 = 全部，2 = 仅 > -65 dB | 刷新路由 |
| `/sendstate` | 触发发送全部状态消息 | 在线探测 |
| `/status/device`（s）、`/status/connection`（f）、`/status/dsp`（f） | 设备名、连接（协议表：1 = 已连接）、DSP 负载 | TotalMix 是否回话 ≠ 设备是否在线：设备未连接时 TotalMix 仍回发保存的配置，connection=0（实测）。R10 用 connection 判断设备在线 |
| `/level/in\|pb\|out/<N>` | 峰值电平 dB，只发变化 | 电平表 |

**安全规则（硬性）**

1. 通道和 Submix 从 0 编号，界面显示加 1；编码层单元测试必须覆盖。
2. **永远不要发送不带值的地址。** 论坛报告：不带值发送 `/input/0/mute` 会把参数写成 1.0，并让服务端卡顿约 1 秒。触发类命令也带值：发 1.0（或协议表规定的 2.0），绝不发小于 0.5 的值。查询只能用请求类地址：`/sendall`、`/sendsettings`、`/sendchan/…`、`/sendmix`、`/sendsubmix/…`、`/sendstate`。
3. 发送层设白名单：只读模式只允许上面的请求类地址；写入类地址只能由“待应用”栏确认后发出（需 `UserConfirmation`）。
   - 实现：`OSCSendGate`（RMEAdapters/GlobalOSC）。只读客户端只暴露请求类 API，网关再按地址白名单复核一次。
4. 部分改动（静音、快照调用）不回传：写后主动重新请求状态再比对。
5. 新建发送先写 -∞ 或很低的电平，确认后再推到目标值。
6. 写入限速，避免批量改动塞满带宽导致丢包。（发送层对所有消息统一限速，默认间隔 20 ms。）
7. TotalMix 通道号与 `xt.<接口>.<方向>:<通道>` 的对照表从 TotalMix 读回：用户确认的条目为 confirmed；从 `/…/name` 回读的名字按 `M<k>-<n>` 解析出的条目为 inferred；对不上的通道不生成路由，只计数提示。
   - 实测 XT 默认名（2026-10-25，`rme-probe`，当时 XT 未连接，读到的是 TotalMix 保存的配置）：输入 `Mic 1`、`Mic 2`、`M1-9`（单声道）、`M2-1/2`（立体声）；输出 `Main`、`Phones 1`、`M1-1`、`M1-3/4`；回放与输出同名。TotalMix 序号：输入 Mic 1–2 为 1–2，M1-1 为 5，M2-1 为 69；输出 Main 为 1，Phones 1 为 5，M1-1 为 7，M2-1 为 71，M3-1 为 135。
   - 解析规则（`TotalMixChannelMap.infer`）：只认硬件默认名 `M<k>-<n>`、`Mic <n>`、`AES`、`AN <n>`、`PH`；输出名被控制室改过（`Main`、`Phones 1`）时改用同号回放的名字（回放 n 与输出 n 是同一硬件口，回放名保持默认）；立体声右声道不发名字，按左声道 +1；回放按定义映射到 `xt.playback.in:n`。
   - 结果（离线配置）：全部 398 条打开的节点都能映射，缺项 0。
   - 隐藏通道（Channel Layout）不回传名字，也就无法映射；要用的通道不要在 TotalMix 里隐藏。

### 7.0 XT 自带话放（Mic 1–2，只读）

- 实测（2026-10-25，`rme-probe --params input:1,input:2`，XT 未连接、读的是 TotalMix 保存的配置）：输入 1、2（名字 `Mic 1`、`Mic 2`）带 `48v`、`gain`、`phase`、`autoset`；**没有** `pad`、`instrument`。
- `48v`、`phase`、`autoset` 为 0/1。`gain` 单位为 **dB**（协议表没写；2026-10-25 实测：用户在 TotalMix 里把 Mic 1 增益调到 60 dB，读回 `gain = 60.0`）。XT 未连接时 TotalMix 照样保存并回发增益改动。
- 只取对照表映射到 `xt.mic.in` 的输入（即 XT 前面板的两路）。TotalMix Aux Device 的前级会出现在 MADI 输入通道上，以后单独处理。
- 名字等于默认的 `Mic n` 时视为没有标签。

### 7.1 写入流程（第一版：TotalMix 发送电平）

**范围**：只写混音节点电平 `/mix/<in|pb>/<源>/<输出>/fader`（dB 浮点）。静音、输出音量、快照等以后再加，加之前先改本节。

**流程**（每一步都不可跳过）：

1. 用户在界面上改一路发送的电平，或“送一路声音”新建发送。改动只进“待应用”栏，不发送任何消息。
2. 点“应用”弹出确认框，逐条列出：链路地址、TotalMix 通道（带 TotalMix 名字，供对照 TotalMix 屏幕）、旧值 → 新值、将要发送的 OSC 原文。对照表条目为 inferred 时标出“对照表为推断”。
3. 只有确认框的“确认发送”能签发 `UserConfirmation`（`ConfirmationGate`），写入经 `OSCSendGate(mode: .readWrite).checkWrite` 复核：带值、读写模式、确认覆盖该操作、操作可写。
4. 发送后用 `/sendsubmix/<输出> 1` 请求该输出的全部节点，回读比对（容差 0.1 dB；关 = 回读 ≤ -65 dB）。结果逐条显示“已核对 / 回读不一致 / 未回读到”。
5. 每批应用记入历史；“撤销”把旧值做成一批新的待应用改动，同样要经确认框。

**电平安全**：

- 新建发送默认 -30 dB（安静起步），在待应用栏里可再调；把“关”写成“关”没有意义，所以不先写 -∞。
- 上限 +6 dB（推子最大值）；抬高超过 10 dB 且目标高于 -20 dB 的改动，确认框里标警示（“关”按 -65 dB 计）。
- 关 = 发送 -300 dB（协议表：under-range 到 -300 dB 为关）。
- XT 未连接时写入只改 TotalMix 保存的配置，不出声，是开发与测试写入的推荐环境；确认框顶部注明当前是否连接。

### 7.2 前级写入（增益、48V、相位）

**范围**：只写三个字段，其余一律拦截。

| 设备 | 增益 | 48V | 相位 | 回读 |
| --- | --- | --- | --- | --- |
| XT Mic 1–2（TotalMix Global OSC） | `/input/<N>/gain`（dB 浮点） | `/input/<N>/48v`（1.0/0.0） | `/input/<N>/phase`（1.0/0.0） | `/sendchan/input/<N> 1` |
| 12Mic（JSON） | `input/analog/<n>/gain`（dB） | `input/analog/<n>/p48`（true/false） | `input/analog/<n>/phase`（true/false） | 读回 `input/analog/<n>`（全 null） |

流程与第 7.1 节相同：改动进待应用栏 → 确认框列出原文 → `UserConfirmation` → 发送 → 回读核对 → 可撤销。

**安全**：

- **打开 48V**：确认框里必须先勾选“这一路没有接带式话筒等不能接幻象电源的设备”，否则“确认发送”不可点。关闭 48V 不需要。
- 增益范围先限定 0–60 dB：XT 实测 60 dB 可写回读；12Mic 上限手册未写，取同一保守值，实机核对后再放开。
- 增益抬高超过 10 dB 标警示。
- 12Mic 写入请求体必须只含这一个叶子（`TwelveMicWriteGate`），由 `precheck` 检查确认凭证与 access。

### 7.3 12Mic 路由写入（阶段 A1）

- 写法（手册 `/routing`）：`{"routing":{"<输出口>":{"<通道>":["<输入口>", <通道>]}}}`；断开写 `["unrouted", 1]`。
- **白名单**（`TwelveMicWriteGate.routeBody`）：输出口只允许 `madi_optical`、`madi_coaxial`（1–64）、`phones`（1–2）；输入口只允许 `analog`（1–12）、`madi_optical`、`madi_coaxial`（1–64）；一次只写一个输出通道。
- 12Mic 路由是“每个输出通道一个来源”，写入会**覆盖**原来的来源：确认框列出旧来源 → 新来源。目标是 `phones` 时标“注意音量”。
- 回读：重读 `routing`（全 null），核对该输出通道的来源。撤销：把旧来源（或 unrouted）做成新的待应用改动。
- 输出页里 12Mic 直通的卡片按单个通道显示（不合并立体声），这样每张卡的改动只对应一个输出通道。

### 7.4 确认方式（用户可选，2026-10-25）

用户要求可以关掉“每次都确认”的流程。在“连接”页选择：

| 方式 | 行为 |
| --- | --- |
| **每次确认**（默认） | 改动进待应用栏，点“应用…”后在确认框里确认才发送（第 7.1 节）。 |
| **快速** | 点下改动即发送并回读核对；**用户这一下点击就是确认**（`ConfirmationGate` 仍只在界面操作里签发）。 |

快速方式下**仍然弹确认框**的情况（硬性，不可关）：

1. **打开 48V**：可能损坏带式话筒，不可撤销；仍须勾选确认。
2. **一次抬高超过 10 dB**（发送电平或前级增益）：可能突然很响。

不变的部分：只写白名单字段；写后回读核对；历史与撤销照常；快速方式下撤销也是点下即发。

### 7.5 跨设备“送一路声音”（阶段 A2）

1. 用户选来源通道与去处通道（可选“左右成对”：s、s+1 → d、d+1 各算一次）。
2. `PathFinder` 在当前快照上搜路径（代价见第 9 节：覆盖已有路由 +100、人工步骤 +10、换控制域 +3）。
3. 路由能力（`StudioSetup.capabilities`）：
   - XT / TotalMix：输入 Mic、AES、MADI 1–3 → 输出 AN、AES、耳机、MADI 1–3；逐通道；混音发送；**可写**（第 7.1 节，A）。
   - 12Mic：输入 analog、MADI 光口 / 同轴 → 输出 MADI 光口 / 同轴、耳机；逐通道；直通；**可写**（第 7.3 节，A）。
   - XTC：输入 Mic、MADI → 输出 ADAT 1/2、MADI；8 路块；**人工**（协议未知，A2）。
4. 计划里每一步标明：自动（TotalMix 新建发送 **-30 dB** 安静起步；12Mic 路由）、沿用已有路由、线缆、人工（XTC 面板）。要覆盖的已有路由逐条列出。
5. 自动步骤进待应用栏（快速方式下按第 7.4 节直接发送）；人工步骤进“需人工完成”清单，用户勾掉为止。
6. 搜不到路径时列出被拦下的原因（格式不符、通道超限、终端采样率等）。

### 7.6 场景（阶段 B1，痛点 9）

- **保存**：把当前读到的真实数据存成一个命名场景：XT 的 TotalMix 发送电平（含电脑回放）、XT 与 12Mic 的前级（增益、48V、相位）、12Mic 路由。演示数据不保存；没读到的设备不保存。地址一律用链路表示法（`xt.mic.in:1` 等），不存 TotalMix 序号。
- **存储**：`~/Library/Application Support/RME Router/scenes/<id>.json`，一个场景一个文件。
- **对比**：列出场景与当前的差异：值不同、场景里有而当前没有、当前有而场景里没有（发送电平）。
- **恢复**：把差异做成待应用改动；场景里没有的发送设为“关”。**恢复一律弹确认框**（不论确认方式），因为一次改动很多项；打开 48V 仍须勾选确认。
- **XTC**（第 6.3 节，2026-10-25 起）：打开“读取 XTC”且读取成功时，场景同时保存 XTC 的数字路由（10 个 8 路输出块：ADAT 1/2、MADI 1–8 … 57–64，各记来源块）与 Mic 1–8 前级（增益、48V、相位）。
  - 路由按块保存：输出块用块首通道（如 `xtc.madi.out:25`），来源存值表 2 的名字（如“MADI 17–24”），有登记端口的同时存块首通道（如 `xtc.madi.in:17`）。
  - 对比按块列差异；恢复时差异进待应用（整块 8 路），仍须确认。
  - 只读（未允许改动 XTC）时可以保存、对比，恢复会逐条说明“未允许本 App 改动 XTC”，不发送。
  - 来源是 ADAT IN、AES IN、电脑回放的块：本 App 没有登记这些端口，能保存、对比，恢复时说明“需在面板上设置”。
  - 旧场景文件没有 XTC 项，照常读取；对比时不涉及 XTC。
  - XTC 时钟、采样率不进场景（只读）。

### 7.7 电平表（阶段 B3）

- 来源：TotalMix Global OSC `/level/in|pb|out/<N>`（峰值 dB，只发变化的值；协议表 A）。前提：TotalMix 的 OSC 设置里勾选 **Send Level Data**。
- 刷新：每 100 ms 从客户端取一次，放在单独的 `MeterStore` 里，只让电平条重绘。
- 显示：输出卡（该输出）、XT 前级卡（该输入）。-60 dB 以下为空，-6 dB 以上黄，0 dB 及以上红（削波）。
- **XT 未连接或 2 秒内没有收到任何电平时显示“无信号”，不显示 0**；XT 已连接但一直收不到电平，提示去勾 Send Level Data。
- 12Mic：手册只写了电平表的显示设置（`levelmeters`），没写读电平数值的接口，暂不显示。

### 7.8 TotalMix 通道条（2026-10-25）

出处（A）：协议表 Protocol 页（2026-10-25 重新下载核对）。参数名另经 `rme-probe --params` 从 TotalMix 读回确认：输出有 `volume`、`mute`、`phase`、`balpan`、`stereo`；输入、回放有 `mute`、`phase`、`width`、`stereo`，**没有 `volume`**（Global OSC 下输入的音量就是各混音节点的电平）。

| 地址 | 取值 | 本 App |
| --- | --- | --- |
| `/mix/in\|pb/<来源>/<输出>/balpan` | -1.0（左）…+1.0（右） | 每条发送的声像，可写 |
| `/output/<N>/volume` | dB；-300 为关；上限 +6 dB（Fader curve 页：faderlin 1.0 = +6 dB） | 输出总音量，可写；-65 dB 及以下按“关”发 -300 |
| `/output/<N>/balpan` | -1.0…+1.0 | 输出的左右平衡，可写 |
| `/input\|playback\|output/<N>/mute` | 1.0 静音 / 0.0 | 可写 |
| `/input\|playback\|output/<N>/phase` | 1.0 反相 / 0.0；**L/R 参数**：立体声右声道用 N+1 单独写 | 可写（按所选声道） |

- 立体声通道：除 L/R 参数（phase）外，一律用左声道编号寻址；选中右声道时自动改写左声道（确认框写明“立体声，作用于左右两声道”）。
- **立体声合并 / 拆分**（2026-10-25 用户要求加入）：`/<bus>/<N>/stereo`，取值 1.0 合并 / 0.0 拆分，N 为奇数号（左声道）。
  - 会改变通道布局，相关的发送、名字都会跟着变，所以**一律明确确认**（快速方式下也弹确认框）；
  - 发送后用 `/sendchan` 回读两个声道，并整体重读一次。
- 不做：`solo`、`pfl`（监听状态）、EQ / 动态 / 混响等效果、`loopback`、`talkbacksel`、`fxsend`/`fxreturn`。
- 写入同第 7.1 节：进待应用栏 → 确认框列 OSC 原文 → 发送 → `/sendchan/<bus>/<N>`（通道参数）或 `/sendsubmix/<输出>`（声像）回读核对 → 可撤销。
- 声像只能改已存在的发送（节点电平 > -65 dB）；没有发送时先“送一路声音”。
- **必须明确确认**（快速方式下也弹确认框）：取消静音（静音 → 不静音，会突然出声）；输出音量一次抬高超过 10 dB 且目标高于 -20 dB。
- 实测提醒（2026-10-25 读取）：当前 TotalMix 配置里 Main 与 Phones 1 的 `volume` 都是 -300（关）。

| E2 | **电脑节点**：拓扑里加“这台 Mac”，点开显示：<br>• XT 的连接方式（USB / Thunderbolt）、采样率、输入输出路数、驱动给的通道名；<br>• 是否正在被使用，以及哪些程序在用（例如 Logic 用了输入、输出）。<br>采样率可改（经 Core Audio，走确认流程） | A（Apple SDK）；进程列表需 macOS 14.2 以上，本机 15 | 接上 XT 后与“音频 MIDI 设置”一致；改采样率后 TotalMix 显示同值 |
| E3 | **设备面板视图（只读）**：新页“设备”：<br>• XT、12Mic、XTC、P16-I 的前面板、后面板示意图，按手册接口表自绘，不用产品照片；<br>• 接口可点，点了在检查器里显示；<br>• 线缆按接线表画出，线上显示 Lock / Sync 和有无信号 | 接口种类、数量出自手册（A）；位置为示意，用户核对一次 | 每个登记端口在图上都有，点了检查器显示对应通道 |
| E4 | **拉线编辑**：从来源接口或通道拖到目标：<br>• XT 硬件输出：TotalMix 新建发送，-30 dB 起步；<br>• 12Mic 输出：12Mic 路由；<br>• XTC 输出块：XTC 路由（需已允许改动）；<br>• 设备之间：改接线表（只是记录实物）；<br>• **电脑录音**：XT 输出的 `loopback`（协议表有），把这个输出的混音送到电脑同号录音通道，**会顶替该通道原来的硬件输入**，须明确确认。<br>不能拖到“电脑回放”：回放是 DAW 送进来的声音，只能当来源，界面直接说明 | A（复用已有写入）；loopback 为 A | 每种拖法都进待应用栏、确认、回读、撤销；不合法的目标拖不上并说明原因 |
| E5 | **DAW / Logic 适配**：<br>• 已有依据（A）：Core Audio 看 Logic 是否在用 XT；TotalMix 回放电平看出 Logic 实际从哪些通道送出声音，在电脑节点上显示“Logic 正在用：回放 1–2、9–10 有声音”；<br>• 读 Logic 的 I/O 标签显示 Logic 里的通道名（C：格式未公开，只读）；<br>• 以后可选：把本 App 的通道名写进 Logic 的 I/O 标签（须 Logic 已退出、先备份、用户同意）；<br>• 每条轨道的输入输出分配、录音待命：**没有公开接口**。候选是 Mackie Control 仿真（能拿轨道名、电平，拿不到 I/O）或读 Logic 界面（易坏），列为研究项，不承诺 | 前两条可做，后面为研究 | 播放时电脑节点能正确列出有声音的回放通道 |
| E6 | **TotalMix 剩余操作**：快照调用与保存（`/snapshot/load\|save`）、控制室（主输出、耳机、Dim、Mono、对讲）、全局静音、撤销 / 重做（全部 A）；采样率经 Core Audio（E2）；时钟源看驱动是否提供 `kAudioDevicePropertyClockSource`（未知，接上后核对） | 多数 A | 列一张“TotalMix 里还要做什么”清单，逐项变成本 App 里的操作，最后只剩一次性设置 |
| E7 | **界面改版**：在 E1–E4 定型后统一重排（设备视图为主、输出卡与检查器为辅） | — | 用户在真窗口里不打开 TotalMix 完成一次日常改动 |

**顺序**：E1（小、立刻有用）→ E2（读取为主）→ E3 → E4 → E6 → E5 研究 → E7。每项先在假设备上测通；凡是写入真设备，仍须用户当次同意。
